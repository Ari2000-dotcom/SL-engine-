SL Guardian

A monitor for an RMS desk. It reads every client's order book, trade book and positions across brokers, and flags any open leg that has no stop-loss, a partial stop-loss, a rejected or cancelled one, or one placed at the wrong price.

READ-ONLY · never places, modifies or cancels orders

Decisions so far

Scope

  • Many client accounts per install
  • v1 brokers: Kotak Neo, Kite, Angel. Others plug in through an adapter.
  • Every leg needs its own SL. There is no basket or MTM exemption.

Runtime

  • Rust (tokio, axum) backend with a React dashboard
  • Daily automatic TOTP login at 08:45 IST
  • Order websocket plus a 5-second full poll as a safety net

Storage and alerts

  • Day data in Parquet, read with DuckDB, wiped at 08:30
  • Live dashboard with sound and a desktop popup
  • Telegram and mobile push come later

Architecture

There is one supervisor task per broker account. Live prices are fetched once per symbol and shared across all accounts. The rule engine is a pure function, so every status in it can be unit-tested.

Leg rules

A leg is identified by account, exchange, symbol and product. It is open while its net quantity is not zero. A protecting order is an SL, SL-M or GTT-SL order on the same leg, on the exit side, in a live state (pending new, open, trigger pending or modify pending).

StatusSeverityCondition
GRACEnoneThe first fill was less than grace_sec ago (default 15s)
NO_SLredNo protecting order exists
SL_REJECTEDredNo protecting order, and the latest SL on this leg today was rejected. The reason is shown.
SL_CANCELLEDredNo protecting order, and the latest SL on this leg today was cancelled
WRONG_SIDEredLong with trigger ≥ LTP, or short with trigger ≤ LTP
PARTIAL_SLamberΣ pending SL qty < |net qty|
OVER_COVEREDamberΣ pending SL qty > |net qty|, so the SL could open a reverse position
TOO_FARamberPCT mode: |trigger − avg| ÷ avg × 100 > max %. RUPEE mode: |trigger − avg| × |qty| × multiplier > max ₹. The admin chooses the mode.
PROTECTEDgreenNone of the above apply
STALE_DATAgreyThe login failed, or the last good poll is more than 20s old. Stale data is never shown as green.

Tables

Two stores. app.duckdb holds the setup (clients, accounts, users, risk settings) and is kept permanently. The daily folder data/YYYY-MM-DD/ holds Parquet files that are deleted at 08:30 IST each morning.

Dashboard

Overview · admin

One card per client with red, amber and green counts and a login-health badge. A sound and a browser notification fire on every new red.

Legs

The live leg_status grid, filtered by client, broker, segment and status. It shows the distance in % and the risk in ₹.

Incidents

Today's open, acknowledged and resolved incidents. Acknowledging silences the sound but does not close the incident.

Risk settings · admin

A PCT or RUPEE mode switch, limits per segment and per client, and the grace period.

Accounts · admin

Add clients, broker accounts and secrets. Shows today's login status and has a retry-login button.

Client view

The Legs and Incidents pages, filtered on the server to the signed-in client's own legs.
